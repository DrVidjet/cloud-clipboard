# cloud-clipboard (clipsync)

[![CI](https://github.com/DrVidjet/cloud-clipboard/actions/workflows/ci.yml/badge.svg)](https://github.com/DrVidjet/cloud-clipboard/actions/workflows/ci.yml)

Общий буфер обмена и общая папка для компьютеров с Linux и Android-телефонов.
Скопировали текст на компьютере — он уже в буфере телефона, и наоборот. Положили файл в
`~/Downloads/share` на компьютере — он появился в `Download/share` на телефоне, и наоборот.

```
 телефон ──┐                       ┌── компьютер
 телефон ──┼──  relay-сервер  ─────┼── компьютер
           │   (облако, VPS)       │
           └──── кабель (adb) ─────┘
```

- **Через сервер** — телефоны и компьютеры в любых сетях, сколько угодно устройств.
- **По кабелю** — телефон, подключённый к компьютеру, синхронизируется напрямую, даже без
  интернета; компьютер пересылает его изменения на сервер и обратно.
- **Настройка телефона один раз**: подключили кабелем — на телефон сам ставится агент, дальше
  он работает и без кабеля. Приложение на телефон не ставится, root не нужен.
- **Шифрование в обе стороны**:
  - содержимое (текст буфера, имена и данные файлов) шифруется на устройствах AES-256-GCM
    ключом из общего секрета — у сервера этого ключа нет, прочитать данные он не может;
  - сам канал устройство ⇄ сервер тоже шифруется AES-256-GCM, с отдельными ключами для каждого
    направления и соединения; устройство и сервер взаимно проверяют, что знают ключ, поэтому
    подменить сервер нельзя. Сертификаты не нужны.

## Установка

Нужны две вещи: **сервер** (любой Linux-VPS с systemd, необязательно) и **компьютер**, к которому
подключается телефон (Linux с Wayland или X11).

### 1. Сервер

На сервере, от root:

```sh
curl -fsSL https://raw.githubusercontent.com/DrVidjet/cloud-clipboard/HEAD/install-server.sh | sudo bash
```

Скрипт ставит Python (если нет), relay в `/opt/clipsync` (с собственным venv), службу
`clipsync-relay`, открывает порт `8765/tcp` в ufw/firewalld, **генерирует секрет** и печатает
готовую команду для компьютеров. Если у провайдера VPS есть свой файрвол — откройте порт там.

Параметры: `--port 9000` — другой порт, `--secret СЕКРЕТ` — свой секрет (или ещё одна «комната»:
у разных секретов свои буферы и папки), `--uninstall` — удалить.

```sh
systemctl status clipsync-relay      # состояние
journalctl -u clipsync-relay -f      # журнал: кто подключился (содержимое туда не попадает)
```

Файлы общей папки сервер хранит зашифрованными в `/var/lib/clipsync`, буфер обмена — только в памяти.

### 2. Компьютер

На каждом компьютере, от своего пользователя (sudo спросится для системных пакетов):

```sh
curl -fsSL https://raw.githubusercontent.com/DrVidjet/cloud-clipboard/HEAD/install.sh | bash -s -- --server IP_СЕРВЕРА:8765 --secret СЕКРЕТ
```

Без сервера (только по кабелю):

```sh
curl -fsSL https://raw.githubusercontent.com/DrVidjet/cloud-clipboard/HEAD/install.sh | bash
```

Скрипт:

1. ставит недостающие пакеты: Python 3.9+, JDK, adb, wl-clipboard/xclip, curl;
2. скачивает проект в `~/.local/share/cloud-clipboard`;
3. выполняет `./clipsync setup` — создаёт окружение `.venv` внутри проекта (Python-пакет
   `cryptography`, scrcpy-server и d8 с проверкой SHA-256, собирает агент для телефона);
4. записывает сервер и секрет в `config.env`;
5. ставит пользовательскую службу `clipsync` (systemd, без sudo) и команду `~/.local/bin/clipsync`.

### 3. Телефон (один раз)

1. **Настройки → О телефоне** → 7 раз нажать **Номер сборки**.
2. **Настройки → Система → Для разработчиков** → включить **Отладка по USB**.
3. Подключить к компьютеру кабелем и подтвердить **«Разрешить отладку по USB?»** (с галочкой
   «Всегда разрешать с этого компьютера»).

Через пару секунд служба на компьютере сама установит и запустит агент. После этого кабель можно
отключить — телефон продолжит синхронизироваться через сервер.

> **После перезагрузки телефона** агент не запускается сам (без root Android не даёт запустить
> его без adb). Достаточно один раз подключить телефон к любому компьютеру с clipsync — агент
> запустится снова. Режим разработчика и разрешение отладки сохраняются.

## Ручная установка (без curl | bash)

```sh
git clone https://github.com/DrVidjet/cloud-clipboard.git
cd cloud-clipboard

# сервер (от root)
sudo ./install-server.sh

# компьютер
./clipsync setup                         # окружение .venv
./clipsync config SERVER IP:8765         # необязательно
./clipsync config SECRET СЕКРЕТ          # тот же, что на сервере
./clipsync install                       # служба systemd
```

Системные пакеты для компьютера:

| Дистрибутив     | Команда                                                                                      |
|-----------------|----------------------------------------------------------------------------------------------|
| Arch / CachyOS  | `sudo pacman -S --needed python jdk-openjdk android-tools wl-clipboard xclip curl`            |
| Debian / Ubuntu | `sudo apt install python3 python3-venv default-jdk-headless adb wl-clipboard xclip curl`      |
| Fedora          | `sudo dnf install python3 java-latest-openjdk-devel android-tools wl-clipboard xclip curl`    |
| openSUSE        | `sudo zypper install python3 java-21-openjdk-devel android-tools wl-clipboard xclip curl`     |

Серверу нужен только `python3` с модулем `venv`.

## Команды на компьютере

```sh
clipsync status          # сервер (доступен ли, подходит ли секрет), служба, телефоны
clipsync logs            # журнал службы
clipsync restart         # перезапуск (после правки config.env)
clipsync run             # запуск в терминале вместо службы
clipsync phone-setup     # переустановить агент на подключённый телефон
clipsync phone-log       # журнал агента на телефоне
clipsync phone-remove    # удалить агент с телефона
clipsync config КЛЮЧ ЗНАЧЕНИЕ
clipsync uninstall       # удалить службу
```

## Настройки

`config.env` (в папке проекта, в git не попадает). После изменения — `clipsync restart`; агент
на телефоне обновится сам при следующем подключении кабеля (или `clipsync phone-setup`).

| Параметр          | По умолчанию             | Значение                                                       |
|-------------------|--------------------------|----------------------------------------------------------------|
| `SERVER`          | пусто                    | `адрес:порт` relay-сервера; пусто — только по кабелю           |
| `SECRET`          | генерируется             | общий секрет, одинаковый на всех компьютерах и на сервере      |
| `SHARE_DIR`       | `~/Downloads/share`      | общая папка на компьютере; пусто — выключить                   |
| `PHONE_SHARE_DIR` | `/sdcard/Download/share` | общая папка на телефоне; пусто — выключить                     |
| `FILE_MAX_MB`     | `2048`                   | файлы больше не синхронизируются                               |
| `USB_PORT`        | `27360`                  | порт связи с телефоном по кабелю; `0` — не использовать кабель |
| `PHONES`          | пусто                    | серийные номера телефонов (`adb devices`); пусто — все         |
| `CLIPBOARD`       | `auto`                   | `auto`, `wayland` (wl-clipboard) или `x11` (xclip)             |
| `NAME`            | hostname                 | имя компьютера в журнале сервера                               |

## Как это устроено

- **Агент на телефоне** (`android/src/clipsync/Agent.java`) — небольшая Java-программа. Компьютер
  кладёт её в `/data/local/tmp/clipsync` и запускает через adb от пользователя `shell`, поэтому
  ей доступен буфер обмена (обычным приложениям Android 10+ читать его в фоне запрещено) и папка
  `Download`. Для доступа к буферу используется [scrcpy-server](https://github.com/Genymobile/scrcpy).
  Агент держит соединения с сервером и с компьютером (через `adb reverse`), следит за буфером и
  сканирует общую папку раз в 3 секунды.
- **Компьютер** (`pc/`) — та же логика на Python: буфер через `wl-paste --watch`/xclip, папка
  сканируется раз в 2 секунды. Для кабеля компьютер поднимает у себя такой же relay
  (`127.0.0.1:27360`), к которому подключаются и телефон, и сам компьютер; так данные телефона
  попадают на сервер даже без интернета на телефоне.
- **Сервер** (`server/relay.py`) пересылает сообщения всем устройствам «комнаты» и хранит последнее
  значение буфера и последние версии файлов, чтобы устройство, бывшее офлайн, догнало остальных.
- Файлы передаются частями по 1 МиБ; при одновременных изменениях побеждает более позднее.
  Удаления тоже синхронизируются. Недописанные файлы (`.part`, `.crdownload`, `.tmp`) пропускаются.
- Последовательность при проверке подлинности: сервер шлёт случайное число, клиент отвечает своим
  числом и HMAC от обоих, сервер подтверждает своим HMAC; ключи канала выводятся из обоих чисел.
  Номера кадров входят в nonce, поэтому повторить или переставить кадры нельзя.

## Если что-то не работает

- **`clipsync status`: «неверный секрет»** — секрет на компьютере не совпадает с сервером:
  `clipsync config SECRET …` и `clipsync restart`.
- **«недоступен»** — сервер не слушает или порт закрыт файрволом (в том числе у провайдера VPS).
- **Телефон не появляется** — `adb devices` должен показывать `device`; `unauthorized` —
  подтвердите запрос отладки на экране.
- **После перезагрузки телефона ничего не синхронизируется** — подключите его кабелем к компьютеру
  с clipsync (см. выше).
- **Буфер синхронизируется только с текстом** — картинки и файлы из буфера не передаются;
  для файлов есть общая папка.
- **Новые файлы на телефоне не видны в «Галерее»** — они лежат в `Download/share` и видны в
  «Файлах»; галерея подхватит их при следующем сканировании медиатеки.

## Тесты и CI

```sh
./clipsync setup
tests/run.sh
```

Тесты не требуют телефона и графического сеанса: поднимают relay, несколько «компьютеров» с
буфером обмена-файлом и агент телефона на обычной JVM, проверяют буфер обмена, файлы (большие,
пустые, подпапки, кириллицу, удаление), доставку устройству, которое было офлайн, работу по кабелю
и пересылку компьютером между кабелем и сервером, отказ при неверном секрете и чужом сервере, и
что на сервере нет открытых данных и имён файлов.

GitHub Actions ([.github/workflows/ci.yml](.github/workflows/ci.yml)) — на каждый push и PR и
еженедельно: shellcheck, ruff, `javac -Werror`; `setup` + тесты в контейнерах Debian, Ubuntu,
Fedora, Arch, openSUSE; установка `install-server.sh` с настоящим systemd и `install.sh`.
Проверка на живом телефоне в CI не делается.

## Структура

```
clipsync               команда: setup / install / run / status / phone-* / …
install.sh             установка на компьютер (curl | bash)
install-server.sh      установка сервера (curl | sudo bash)
config.env.example     пример настроек
requirements.txt       Python-пакеты и системные требования
pc/clipsync.py         команды, буфер обмена ПК, управление телефонами по adb
pc/sync.py             синхронизация буфера и папки, соединения
server/relay.py        relay-сервер и протокол (общий с ПК)
android/src/clipsync/  агент для телефона
tests/run.sh           тесты без телефона
.github/workflows/     CI
```
